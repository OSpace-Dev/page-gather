# 需求与功能设计 v0.1

## 1. 目标与已确认约束

构建个人使用的网站自动化采集平台。服务器运行真实 Chrome，用户在自动化之前手动登录，系统每天按计划采集数据，必要时签到；数据集中存储，通过网页查看，有关注的新增或变化时通知 iPhone。

| 项目 | 已确认需求 |
|---|---|
| 用户与账号 | 个人使用，仅使用自己的目标网站账号 |
| 登录 | 用户预先手动登录，不要求自动输入密码、验证码或绕过验证 |
| 浏览器控制 | 不使用 Playwright；直接通过 CDP 控制真实有界面 Chrome |
| 操作 | 以采集和查询为主，允许少量签到等点击 |
| 执行频率 | 一般每天一次，支持手动触发 |
| 扩展 | 按网站增加、禁用、删除插件 |
| 数据 | 通过接口回传中心，存储并提供查询页面 |
| 移动端 | PWA，接入 iOS Web Push |
| 当前交付 | 设计文档与可编辑图形，暂不开发业务代码 |
| 目标服务器 | CPU 资源较低、内存充足、可运行容器；默认 SQLite |
| 部署入口 | 已有域名、NGINX 与 HTTPS 配套；中心服务独立容器，复用既有入口 |

“真实浏览器”落实为服务器有界面 Chrome、持久化用户目录及可人工访问的桌面。采用直接 CDP 控制，不使用 Playwright；不注入伪装浏览器指纹或绕过网站验证的脚本。使用 Chrome 或直接 CDP 都不能保证不被目标网站识别或封禁，首个站点需要按其规则实际验证，遇到风险提示停止任务并交由用户处理。登录必须发生在服务器这份浏览器环境内；本地电脑 Chrome 的登录不会自动同步过去。

## 2. 首版范围

首版包含：个人管理端认证、浏览器手动登录入口、账号会话状态、代码插件管理、任务配置、每日调度、手动执行、执行记录、数据去重和历史、站内通知、PWA 推送、失败诊断与恢复。

首版暂不包含：多租户、公共插件市场、可视化 RPA 编排器、自动破解验证码、多服务器浏览器池，以及购买、转账、发布等复杂写操作。签到作为单独声明的有副作用能力处理。

## 3. 核心使用流程

### 3.1 首次接入网站

1. 安装可信插件，登记插件版本与参数结构。
2. 创建浏览器配置档案，绑定一个持久化 Chrome 用户目录。
3. 用户进入“人工操作模式”，通过受保护的远程桌面打开服务器浏览器。
4. 手动完成登录；网站身份凭据留在浏览器目录中。
5. 结束人工操作，平台执行插件登录探测。探测通过才允许执行任务。
6. 配置网站参数、每天执行时间、时区及通知规则。
7. 手动试运行，核对采集结果；若包含签到，再检查签到结果。
8. 启用每日调度。

登录状态显示为“未知／上次验证有效／需要登录／人工操作中”，同时展示最后检查时间。不能只根据 Cookie 文件存在认定有效。

### 3.2 每日执行

到达计划时间后生成执行记录；执行器领取任务并锁定浏览器配置档案，检查登录，运行插件，将结果可靠上报。中心完成入库与变化判断，生成站内通知和待发送事件，后台发送 Web Push。

运行中的任务不因用户打开管理页面而中断。用户进入远程浏览器前必须等待当前任务结束，或明确取消并等执行器释放浏览器；不允许直接同时操作。

### 3.3 会话过期与异常

发现登录过期或验证码时，暂停该配置档案下任务，生成去重后的站内提醒；推送已启用时同步提醒。用户手动处理后点击“检查并恢复”。探测通过后恢复任务，对有效期内错过的每日执行补跑一次。

页面结构变化、字段缺失、超时和采集范围不完整需分别记录。失败不写入伪造的空结果，不据此删除历史数据。

### 3.4 签到

插件声明签到能力，任务配置显式开启后才执行。每次先查询当天签到状态，已完成则跳过；否则记录操作意图，再点击并核验。

点击后超时或断网，进入“结果待核验”。系统可执行只读核验；无法确认时暂停写操作并提示用户，不能直接重新点击。只有核验明确未执行，且插件定义可安全再试时，才允许受控重试。

## 4. 页面与功能

| 页面 | 核心内容与操作 |
|---|---|
| 概览 | 今日计划、最近成功时间、待登录/待处理事项、未读通知 |
| 浏览器与会话 | 档案、锁定状态、上次验证、进入人工模式、检查并恢复 |
| 插件 | 已安装版本、能力、参数说明、启用/禁用、引用关系；首版通过部署安装 |
| 任务 | 插件、浏览器档案、参数、每日时间、时区、签到开关、启停、手动执行 |
| 执行详情 | 阶段、时间、错误分类、采集数量、完整性、截图、上报和操作结果 |
| 数据 | 来源/类型/时间筛选、全文或关键词搜索、列表、详情、变化历史、源链接 |
| 通知 | 站内消息、已读状态、关注规则、设备订阅、发送状态 |
| 设置 | 调度时区、PWA 安装引导、通知授权、存储保留策略 |

不在普通页面展示 Cookie、CDP 地址、推送订阅密钥。截图和运行追踪仅在认证后访问。

## 5. 默认行为建议

| 项目 | v0.1 建议 |
|---|---|
| 调度 | 每日指定本地时间；默认 Asia/Shanghai，具体时间由任务设置 |
| 并发 | 整个执行器一次一个任务；人工操作期间暂停自动领取 |
| 首次采集 | 建立基线，默认只推送一次摘要，不逐条推送历史数据 |
| 变化通知 | 新增和插件声明的重要字段变化；忽略抓取时间等噪声 |
| 漏跑 | 24 小时内补最近一次，丢弃更早计划，不积压多天任务 |
| 删除判断 | 首版不自动将“本次未出现”认定为删除 |
| 重试 | 只读瞬时错误最多重试两次；登录和页面结构错误等待处理 |
| 通知 | 站内消息持久化；推送不作为送达或已读保证 |
| 诊断保留 | 成功日志 30 天、失败截图/trace 14 天；业务数据暂不自动清理 |

这些值为待验证默认值，不是用户已指定的限制。每日重复任务按目标站点日期执行签到，不能默认所有站点与调度器时区一致。

## 6. PWA 与推送

复用已有 NGINX 提供的 HTTPS 安全上下文，项目实现 manifest、Service Worker 和标准 Web Push，不负责域名与证书部署。iOS/iPadOS 16.4 起支持添加到主屏幕的 Web 应用推送；授权由用户点击按钮触发。用户从主屏幕打开 PWA 后订阅，服务端将订阅绑定到个人账号和设备。

一个账号支持多台设备。点击通知进入需要认证的数据详情；没有权限或记录已不存在时显示适当页面。通知仅含简短摘要，敏感数据打开应用后读取。设备注销时解除绑定；端点返回 404/410 时清理失效订阅。

拒绝权限后显示状态与系统设置指引，不反复弹窗。前台、锁屏、PWA 关闭后的效果需用真实 iPhone 验证。推送服务接受消息不能证明手机展示成功；系统设置、网络和专注模式可能延迟提醒。

参考：https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/

## 7. 首版验收标准

- 用户能在服务器 Chrome 手动登录，重启容器后仍使用原用户目录；若网站主动失效，能正确提示重新登录。
- 每日任务按指定时区产生一条计划执行，重启后按补跑规则恢复，不重复执行同一计划。
- 同一浏览器不会被人工和自动化同时操作。
- 对同一采集结果重复上报，不增加重复业务记录、变化事件或通知。
- 会话失效、页面改版、执行器崩溃能在界面看到原因及恢复入口。
- 签到点击后的不确定结果不会触发盲目重试。
- iPhone 上能完成安装、订阅、接收通知并打开正确详情；拒绝通知时仍可查看站内消息。
