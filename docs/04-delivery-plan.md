# 实施与验证计划 v0.1

## 1. 阶段与交付

| 阶段 | 交付 | 进入下一阶段的条件 |
|---|---|---|
| P0 设计基线（当前） | 需求、架构、契约、图形、验收计划 | 文档可审阅；实际网站待指定 |
| P1 浏览器可行性 | Chrome 容器、远程登录、持久化目录、直接 CDP 连接与单站点探测 | 用户能在服务器手动登录，重启后验证会话并采集示例；无 Playwright 依赖 |
| P2 最小闭环 | 一个插件、单任务、手动执行、API 入库、数据列表 | 连续重复执行不产生重复数据，失败有日志 |
| P3 每日稳定执行 | 调度、租约、互斥、spool、重试、登录恢复 | 验证重启、漏跑、断网、人工模式竞争 |
| P4 通知闭环 | 变化事件、基线、站内消息、Outbox、PWA 推送 | 真实 iPhone 验证安装授权、锁屏推送和详情跳转 |
| P5 签到与维护 | 操作日志、只读核验、插件升级、清理备份 | 点击后故障不会盲目重试；完成备份恢复演练 |

先验证真实站点的登录保持和采集路径，再投入通用界面。若首站点不需要签到，P5 签到能力可留待第二个实际需求，不影响采集闭环。

## 2. 建议后续代码目录

```text
apps/
  web/                  # Vue 3 + Naive UI 管理界面与 PWA（推荐）
  server/               # 配置、调度、入库、通知
  worker/               # 浏览器生命周期与插件执行
packages/
  contracts/            # API Schema 与共享类型
  plugin-sdk/           # 插件契约及运行工具
plugins/
  first-site/           # 首个实际站点，名称后定
infra/
  compose/              # 部署、卷、健康检查
  browser/              # Chrome、显示环境、noVNC 镜像
  migrations/           # 数据库迁移
```

当前不创建这些空业务目录，也不安装运行依赖；先保留设计资料。

## 3. 验证矩阵

| 场景 | 预期结果 |
|---|---|
| 同一计划被调度两次 | 仅一条自动执行记录 |
| 手动触发重复 HTTP 请求 | 同请求键返回同执行记录 |
| 人工模式与任务领取竞争 | SQLite 短写事务和条件更新保证互斥，只有一方持有浏览器 |
| SQLite 写入繁忙 | 有限退避，不重复领取或提交；心跳不因长事务被饿死 |
| WAL 模式运行中备份 | 一致性备份恢复后通过完整性与外键检查，已提交数据不丢失 |
| 中心容器重建 | 挂载原数据库目录，数据库与 WAL 正确恢复；执行器无数据库访问权限 |
| noVNC 意外断开 | 仍为人工模式，不突然恢复自动任务 |
| 容器重建 | 挂载原 Chrome 档案，用户目录不被初始化覆盖 |
| CDP 断连 / 导航 / iframe / 新标签页 | 正确重建页面会话与上下文，显式超时，不重放不确定点击 |
| 自动化依赖检查 | 不引入 Playwright 或间接包装依赖，插件仅使用项目 CDP 接口 |
| 登录失效或验证码 | 暂停档案并提示，其他错误不伪装成登录成功 |
| 网络断开但 Chrome 仍活着 | 执行器在租约失效前停止；中心不立即启动第二份任务 |
| 抓取结束后中心不可用 | 原子写 spool，恢复后上报，不重复访问或签到 |
| 中心已提交、响应丢失 | 重传返回原收据，数据/版本/通知均不重复 |
| spool 属于过期 attempt | 走恢复协议，原 collection 序号不变，不覆盖更新的已提交结果 |
| 旧 A 恢复，新 B 已入库但为 PARTIAL | 旧批次 STALE，B、版本和通知不变；旧载荷归档确认后才清理 spool |
| 新 B 已入库但未报告终态即崩溃 | 按已提交水位拒绝旧 A，与 RUNNING/RECOVERING 状态无关 |
| 新内容未变或有效空结果已提交 | 仍推进档案水位，迟到的旧批次不能覆盖或新增旧实体 |
| 同档案不同任务/插件/范围乱序 | 共用档案水位，旧范围整批归档，提示可重新只读采集 |
| 已 APPLIED 的响应丢失，随后又有更新 | 重传返回原 APPLIED 收据，不改判 STALE、不重复更新 |
| 相同 collection 更换 submission 或同 ID 改载荷 | 返回 409，保留 spool，不新建版本 |
| collection 登记响应丢失 | 同登记请求键返回原 ID/序号，不因重试产生新采集顺序 |
| 换租约恢复结果 | 授权字段变化不改变业务 hash；collection 绑定不变 |
| 恢复预检后更新结果先提交 | submissions 事务重查水位，旧批次归档，不依赖预检放行 |
| 数据、收据与水位提交中断 | 原子提交或全部回滚；重试不会出现水位推进但业务数据未提交 |
| STALE 归档响应丢失或归档失败 | 原收据可重取；失败继续保留 spool，不修改业务数据 |
| 字段内容 A→B→A | 保留两次变化，不因历史 hash 已存在而丢失回退 |
| 首次采集大量旧数据 | 一条基线摘要，不逐条轰炸 |
| 分页只读取一部分 | 标记 PARTIAL，不推断删除，不建立完整基线 |
| 签到前崩溃 | 恢复先查询当天状态 |
| 签到成功但回执丢失 | 核验到已签到，跳过再次点击 |
| 签到结果不可查询 | 等待人工处理，不盲目再点 |
| 取消与提交同时发生 | 记录明确保留已提交结果，停止后续动作 |
| Outbox 处理时重启 | 站内消息保留，未完成设备继续投递，允许合并重复推送 |
| 推送端点 410 | 删除失效订阅，不影响其他设备 |
| iPhone 拒绝通知 | 页面显示拒绝状态，站内通知正常 |
| iPhone 锁屏/PWA 已关闭 | 在允许条件下收到通知；点击进入正确详情，需登录则先登录 |
| 未授权请求附件或远程桌面 | 拒绝访问，不泄露 Chrome 会话 |
| 磁盘满 | 停止新任务、显示告警、保留未确认结果 |
| 备份恢复 | 数据、配置、VAPID 恢复；浏览器会话不可移植时允许手动重登 |
| 容量增长 | 真实行宽的 10 万/100 万及预计三年数据集验证查询、写入和备份；记录实测而非承诺上限 |
| 裁剪旧日志 | collection/收据/提交水位和未决操作键保留，旧提交重传仍防重 |
| 现有 NGINX 接入 | API 保留路径、SPA 深链接正常；API/资源错误不回退 HTML；Secure Cookie 和代理头正确 |
| PWA 发布与退出 | 静态资源可更新，旧版兼容；不缓存敏感 API 数据；退出清理个人状态 |
| 结束人工会话 | 已建立的 noVNC WebSocket 也被关闭或撤销输入，不能继续操作 |
| iPhone UI | 三个样例页验证弹层、键盘、375px 布局与44px触控，组件库不代替适配验证 |

验证采用少量关键单元测试（调度/幂等/状态转换）、数据库集成测试与真实浏览器端到端试跑。静态设计阶段仅检查文档链接、图形文件结构与导出，不声称这些业务场景已经验证通过。

## 4. 实施前仍需确定

1. 第一个具体网站、采集页面、需要展示的字段，以及是否签到。
2. 服务器系统、CPU 架构与核数、可用内存、本地磁盘和现有 NGINX 的运行位置/静态文件发布方式；已确认 CPU 资源较低、内存充足且可运行容器，默认 SQLite，域名及 HTTPS 由既有设施提供。
3. 每天期望执行的时间，网站签到的业务时区。
4. 新增与更新的关注规则，是否希望首日接收摘要。
5. iPhone 系统版本，是否接受添加到主屏幕和手动开启通知。

这些信息不阻碍当前通用设计。P1 之前必须明确首个站点与服务器环境，才能验证兼容性。
