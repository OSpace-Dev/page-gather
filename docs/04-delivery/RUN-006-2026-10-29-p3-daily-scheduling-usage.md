# P3 每日计划使用说明

> 文档编号：RUN-006 | 建立日期：2026-10-29 | 最后更新：2026-10-29
> 类型：使用手册 | 状态：P3开发交付（已完成WSL验收与代码修复复审）

## 开发预览入口

P3管理页面：**http://127.0.0.1:18081/**，用户名 `admin`。密码由该独立部署初始化时随机创建，不复用P2；在自己的可信Windows终端读取，不把输出发给助手或提交仓库：

```powershell
wsl -d Ubuntu-22.04 -- docker exec page-gather-p3-dev-server-1 head -n 1 /run/secrets/admin-password
```

`/run/secrets/admin-password`是容器内约定路径，不是宿主位置。开发验收已保存一次真实每日计划采集，运行记录可直接查看；当前任务配置恢复为09:00/Asia/Shanghai、计划关闭。你可在页面编辑实际时间后启用。

## 1. 每日计划与手动执行

P3在P2的任务页面增加每日计划。手动运行仍可使用，不会因为手动点一次就开启自动日程。现有数据库升级后所有旧任务日程默认关闭，09:00/Asia/Shanghai只是初始填写建议，不代表已经替用户启用。

进入任务的“编辑参数”，选择每日计划开关、当地HH:mm和IANA时区，再保存。任务启用与日程启用是两层开关：任务停用后不运行，之后重新启用只安排未来一次。界面显示下一计划时间和时区，运行详情标明手动或每日触发及原计划时刻，不把实际补跑时间冒充计划时间。

## 2. 漏跑、忙碌和暂停

- 正常每天按配置时间创建一次计划run。
- 服务停机后恢复，只补最近24小时内最新一次，较旧日程跳过，不集中重放多天网页请求。
- 同任务已有排队、运行或恢复中的run，本次自动slot跳过并记录被占用，不堆积重复run。
- 人工模式或worker离线时，计划run可以排队，但不抢占浏览器；领取前重新检查是否超24小时、日程是否被关闭或修改。
- 修改时间、时区或停用日程，会清理旧日程的排队run，不突然取消已经运行的任务；取消运行使用原“取消采集”操作。
- 关闭后重新开启，不补关闭期间的历史日程。未完成OPEN草稿不自动续采；已SEALED结果上报失败只重传，不重新访问网页。

任务卡显示调度处理摘要/原因，概览显示调度器健康和最近tick。错误或跳过不是“采集成功”，没有正文时不提供伪造结果。

## 3. 时区与夏令时

时间属于所选时区，不是服务器本地时区。夏令时重复分钟只取较早一次；不存在的时间顺延到当天首个有效时刻（如02:30不可用则03:00），不会同一天创建两次。默认Asia/Shanghai不采用当前夏令时切换，但仍通过同一算法计算。

## 4. 边界与安全

本阶段的自动任务仍仅针对已安装的可信公开GitHub插件，不意味着已经验证所有需登录网站。遇到403/429、挑战、页面结构变化时按原有规则停止或部分完成，不无限自动重抓。PWA推送、签到不在P3已实现范围。

服务器以后由用户部署；当前以WSL开发环境验收，不提供改系统时钟或任意设置调度运行时钟的生产HTTP接口。所有日程、计划执行和结果保存在部署目录data内SQLite，自动run的slot有唯一约束，不能通过重启制造重复。

## 5. 开发环境与以后部署

P3继续使用 `compose.p2.yaml` 提供server、worker和NGINX页面，文件名保留以兼容P2，不需要额外调度器容器。新部署先在Linux原生文件系统的部署目录执行 `bash scripts/init-p2.sh`，沿用data子目录及私有配置文件；不要复用活动的P1/P2 Chrome档案。

本轮P3副本设置的配置如下，`.env`仅保存在部署目录，不进Git：

```dotenv
PAGE_GATHER_WEB_PORT=18081
PAGE_GATHER_PUBLIC_ORIGIN=http://127.0.0.1:18081
PAGE_GATHER_P2_BROWSER_PORT=16081
PAGE_GATHER_NOVNC_ORIGINS=http://127.0.0.1:16081
VITE_BROWSER_PREVIEW_URL=http://127.0.0.1:16081/vnc.html
```

其他镜像版本、HTTP开发边界、凭据初始化和Chrome沙箱要求仍见 [P2使用手册](RUN-005-2026-10-25-p2-usage.md)。调度自动随中心服务启动，任务级日程默认关闭。不要为验证补跑修改系统时间；算法和故障用临时库测试。

当前P3服务保留运行；旧P1/P2本轮检查时均已停止，没有被自动启动或改状态。重启P3服务时使用同一部署副本的Compose配置和 `-p page-gather-p3-dev`，避免另起空data。以后服务器部署由用户亲自进行，不需要现在执行。
